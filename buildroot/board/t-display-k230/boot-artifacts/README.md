# T-Display K230 Boot Artifacts

This directory is the default local input location for `post-image.sh`.

The platform does not commit bootloader binaries here. Place local artifacts
here only when generating a hardware boot image.

Required canonical filenames for local bootloader binaries:

| File | Meaning | Reference source name |
| --- | --- | --- |
| `spl.bin` | K230 first-stage loader | `uboot/fn_u-boot-spl.bin` |
| `u-boot.bin` | U-Boot image | `uboot/fn_ug_u-boot.bin` |
| `fw_jump_add_uboot_head.bin` | OpenSBI jump image wrapped for the SDK U-Boot `blinux` flow | `boot/fw_jump_add_uboot_head.bin` |

The accepted first source for these files is the K230 Linux reference path
selected in this board profile. During current bring-up, that means the
bootloader artifacts must be derived from the `kendryte/k230_linux_sdk`
baseline or from an explicitly documented local mirror of that source:

```text
<k230_linux_sdk-output>/images/uboot/
```

Use the importer after the pinned SDK has produced its images directory:

```sh
buildroot/board/t-display-k230/tools/import-boot-artifacts.sh \
  <k230_linux_sdk>/output/k230_canmv_v3_defconfig/images
```

The importer writes `manifest.local` beside the binaries. That manifest is a
local validation artifact and remains ignored by git.

See [../bootloader.md](../bootloader.md) for the complete
build procedure, host requirements, accepted source commit, and observed hashes.

The U-Boot environment block is not a local binary input. It is generated by
Buildroot from:

```text
buildroot/board/t-display-k230/uboot-linux.env
```

Buildroot writes the generated environment image as:

```text
output/t_display_k230_vision/images/uboot-env.bin
```

`post-image.sh` stages that generated file as `boot-artifacts/u-boot.env.bin`
only inside the Buildroot images directory before running `genimage`.

Do not blindly use non-Linux reference payloads as Linux payload artifacts.
Artifacts from the LilyGO/CanMV RT flow are hardware and boot-mechanism
evidence only; they are not accepted Linux platform components.

The current platform image follows the selected K230 Linux SDK `blinux` shape:
an ext4 boot partition containing `fw_jump_add_uboot_head.bin`, `Image`, and
`k.dtb`.

If a future bring-up chooses a hidden-payload path, that must be treated as a
new boot policy and documented against the current K230 Linux reference source.
Do not adopt a hidden slot, image name, or block offset because it appeared in a
non-Linux reference flow.

You may also set `TDVP_BOOT_ARTIFACT_DIR` to point `post-image.sh` at another
directory with the same canonical bootloader binary filenames.
